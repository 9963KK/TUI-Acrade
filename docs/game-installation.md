# 游戏安装规范

| 项目 | 内容 |
| --- | --- |
| 版本 / 状态 | 0.8 / 已确认的产品方向，取代[游戏安装管理规范](game-management.md)（预构建包模型） |
| 需求来源 | U-18 至 U-23，见[设计来源](README.md#设计来源) |
| 核心 | 游戏接入后能在这台电脑上正确启动；只有安装完成的游戏出现在游戏厅 |

已实现（2026-10-09）：启动与安装界面、三类来源、Python 环境、隔离存档试运行、安装记录、卸载／修复、搜索和命令行检查。实现入口为 `platform/internal/install/manager.go` 与 `platform/internal/lobby/platform.go`；macOS 真实终端测试见 `tests/test_terminal.py`。

## 1. 基本模型

玩家是使用命令行的程序员，自己用 git 获取平台仓库。平台不负责分发，只负责**把游戏正确地接入并启动**。

### 1.1 游戏来源

| 来源 | 位置 | 获取方式 | 卸载时 |
| --- | --- | --- | --- |
| 内置 | 平台仓库的 `games/<文件夹>/` | 随平台仓库一起 `git clone` / `git pull` | 删除运行环境，源码保留在仓库中 |
| git | 单独的 git 仓库，`game.json` 在仓库根目录 | 平台以前台方式执行 `git clone --depth 1` 到程序目录 | 删除克隆目录与运行环境 |
| 本地目录 | 本机任意目录（游戏开发者使用） | 不复制，登记该目录路径 | 删除运行环境，目录本身不动 |

任何来源在所有卸载方式下都保留该游戏的存档目录；删除存档是单独的明确操作。

### 1.2 游戏状态与显示规则

| 状态 | 含义 | 游戏厅 | 安装游戏页面 |
| --- | --- | --- | --- |
| 可安装 | 内置游戏或已知来源尚未安装 | 不显示 | 显示“可安装” |
| 已安装 | 用户确认安装，运行环境就绪，并通过全部检查 | 显示，可启动 | 显示“已安装”，Enter 询问卸载 |
| 需要修复 | 曾经安装，但之后的检查未通过（例如 `git pull` 后或系统 Python 变化） | **显示但不能启动**，标明原因，可查看检查报告 | 显示“需要修复”，Enter 重新安装 |
| 本机不支持 | 清单声明的系统、架构或运行环境本机无法满足 | 不显示 | 显示“本机不支持”，不可选，底部说明原因 |

**显示规则**：游戏只有在“通过检查 + 运行环境已安装 + 用户确认安装”三者都满足后才出现在游戏厅（U-19）。需要修复的游戏保留在游戏厅中，方便玩家自行排查（U-21）。安装数量不设上限（U-22）。

## 2. 界面

### 2.1 启动界面

每次运行 `tplay` 先进入启动界面，三个选项：**进入游戏厅 / 安装游戏 / 退出游戏厅**（U-20）。上方展示大手柄像素图标、平台名称与宣传语，下方的三个选项逐行居中；选中按钮反色显示，并在两侧显示箭头。图标、菜单与提示作为整体在窗口中居中，纯文本终端使用 ASCII 图标。尚未安装任何游戏时，光标默认停在“安装游戏”。在游戏厅或安装页面按 `Q` / `Esc` 回到启动界面；在启动界面选择退出或按 `Q` 才退出程序。

### 2.2 安装游戏

列表每行只显示名称与状态，选中行整行反色；当前行的运行环境要求与不可安装的原因显示在底部一行。

- 可安装 / 需要修复：Enter 弹出确认框，列出将要执行的操作（克隆、创建虚拟环境、安装依赖、试运行），确认后显示逐步进度与结果。
- 已安装：Enter 询问卸载，并说明存档会保留。
- 列表最后一项为“＋ 从 git 地址或本地目录添加…”：Enter 打开输入框，平台根据输入判断是 git 地址还是本地路径。
- 不提供多选；每次对当前行操作。

### 2.3 游戏厅

- 只显示已安装与需要修复的游戏。
- 按 `/` 进入搜索，按名称、英文名、标签和 ID 过滤，`Esc` 清除（U-22）。
- 需要修复的游戏卡片变灰，底部说明失败的检查项；Enter 打开检查报告（失败项、原因、日志位置），不会启动游戏。

## 3. 安装流程

1. **获取**：内置与本地目录无需获取；git 来源克隆到程序目录下的暂存位置。克隆在前台进行，终端交给 git，便于输入 SSH 口令、确认主机指纹或 HTTPS 凭据。
2. **读取清单**：校验 `game.json`（[接入规范](game-integration.md)），ID 不得与已登记的其他来源的游戏重复。
3. **确认**：展示名称、作者、来源（git 地址与提交号 / 路径）和将要执行的命令，用户确认后继续。平台会执行游戏仓库提供的代码与依赖安装，只应添加信得过的来源。
4. **准备运行环境**：按 `requirements.python` 选出符合版本的解释器；声明了依赖时为该游戏创建独立虚拟环境并安装依赖（前台执行，输出直接显示）。虚拟环境放在平台目录中，不写入游戏目录。
5. **检查**：见第 4 节。
6. **登记**：全部通过后写入安装记录，游戏出现在游戏厅。任何一步失败都不登记；git 来源默认删除克隆目录，可选择保留现场以便排查。

## 4. 检查

### 4.1 静态检查

| 项目 | 内容 |
| --- | --- |
| 清单 | 格式、字段与路径约束，见接入规范 |
| 系统与架构 | `requirements.os` / `arch` 与本机匹配 |
| 解释器 | 找到满足 `requirements.python.version` 的 Python；平台依次尝试 `TUI_ARCADE_PYTHON`、`python3`、`python`、`python3.<n>` |
| 模块 | `requirements.python.modules` 中的模块均可导入（例如 Windows 上的 `curses` 会在此失败） |
| 入口 | 启动命令的入口存在且可执行 |

### 4.2 试运行

平台在一个与当前窗口同尺寸的虚拟终端中，按正式启动的方式（相同的环境变量与工作目录）启动游戏：

1. 5 秒内必须有画面输出；平台代替终端应答常见的终端查询（光标位置、背景色）。
2. 输出后仍在运行，或已以退出码 0 结束。
3. 发送 Ctrl-C，3 秒内退出视为通过；未退出则发送 SIGTERM，3 秒内退出视为通过并记录提示；仍未退出则强制结束，判定失败（“无法用 Ctrl-C 或 SIGTERM 退出”）。

试运行使用独立的数据目录副本，不改动玩家存档。Windows 上的试运行需要 ConPTY，首版暂不提供，检查报告中注明“未试运行”。

### 4.3 重新检查

安装记录保存游戏目录内容的指纹（排除 `.git` 与缓存）。每次进入游戏厅时，对内容发生变化的游戏重新执行静态检查；通过则更新指纹，未通过则标为需要修复。重新安装会执行完整检查，包括试运行。

### 4.4 命令行

`tplay check [ID 或路径] [--run]` 对已登记的游戏或指定目录执行静态检查，`--run` 同时试运行，输出逐项结果；有失败项时退出码非零，可用于 CI 审核接入 PR（U-03）。

## 5. 数据布局

```text
<用户数据目录>/installed.json          安装记录（唯一事实来源）
<用户数据目录>/games/<id>/             游戏存档（卸载时保留）
<程序目录>/games/<id>/                 git 来源的克隆
<程序目录>/envs/<id>/                  虚拟环境
<程序目录>/.staging/                   暂存；启动时清理
<日志目录>/<id>/install.log            安装与检查日志
<日志目录>/<id>/check.log              命令行重新检查日志
```

安装记录每项包含：ID、来源类型、路径、git 地址与提交号、使用的解释器、虚拟环境、内容指纹、状态、最近一次检查结果与时间。写入方式为临时文件 + 同步 + 原子替换，并保留上一份为 `.bak`。修改安装记录时持有跨进程文件锁。

每个游戏另持运行／安装锁，避免运行期间卸载或并发修复。暂存源码与新环境持有租约，其他窗口不会清理活动安装。源码移动与卸载先写事务日志；启动时根据有效安装记录恢复未提交的目录，清理已提交事务。失败的修复保留原环境；显式保留的现场不会自动删除。

## 6. 被取代的决定

U-18 使以下内容不再适用：U-05（从 GitHub 目录选择安装）、U-06（最多 12 个）、U-10（预构建可运行包）、U-11（下载平台的安装命令），以及[游戏安装管理规范](game-management.md)整份。平台在本地开发阶段通过 `scripts/install-tplay.sh` 提供 `tplay` 命令。

## 7. 验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| IN-01 | 首次运行 `tplay` | 启动界面光标在“安装游戏”；游戏厅为空并提示去安装 |
| IN-02 | 安装内置游戏 | 确认 → 检查 → 试运行通过后出现在游戏厅 |
| IN-03 | 粘贴 git 地址安装 | 前台克隆，确认信息含地址与提交号，通过后出现在游戏厅 |
| IN-04 | 登记本地目录 | 不复制目录；修改代码后进入游戏厅时自动重新检查 |
| IN-05 | 缺少模块或 Python 版本过低 | 在确认前或检查阶段失败，原因明确，不登记 |
| IN-06 | 游戏启动即崩溃或 5 秒无输出 | 试运行失败，报告退出码与日志位置 |
| IN-07 | 游戏无法用 Ctrl-C / SIGTERM 退出 | 试运行失败，终端状态正常 |
| IN-08 | 已安装游戏在 `git pull` 后检查失败 | 游戏厅中显示为需要修复，可查看报告，不能启动 |
| IN-09 | 卸载内置 / git / 本地游戏 | 分别按 1.1 处理，存档保留 |
| IN-10 | ID 与已登记游戏冲突 | 拒绝安装并说明 |
| IN-11 | 游戏厅搜索 | `/` 过滤，`Esc` 清除 |
| IN-12 | 安装中途强制退出平台 | 下次启动清理暂存，安装记录不受影响 |
