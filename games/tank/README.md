# 坦克大战 · TANK BATTLE

完整导入经典 Battle City 的 35 关地图和敌军出场队列，提供独立的单人战役、主菜单、选关、暂停、重试、逐关结算和通关流程。TUI Arcade 负责启动游戏；游戏内部的菜单和战役由坦克大战自己管理。

## 运行

- 从游戏厅：在仓库根目录运行 `./play.sh --game tank`，进入坦克大战主菜单。
- 单独运行：`cd games/tank && python3 -m tank_battle`。

需要 80 × 24 以上的 UTF-8 终端、Python 3.10+ 与标准库 `curses`，当前支持 macOS 和 Linux。彩色终端显示块字符与 Braille 砖墙；`ARCADE_ASCII=1` 或 `NO_COLOR=1` 使用 ASCII 图案。

## 游戏流程

主菜单提供开始新战役、继续当前战役、选择关卡、操作说明与退出。继续当前战役保留本次进程内的战场；关闭程序后只保留最高分，不保存战役。

按 `P` / Esc 打开暂停菜单：

| 选项 | 行为 |
| --- | --- |
| 继续游戏 | 原地恢复，生命、地形与敌军均保留 |
| 重试本关 | 确认后恢复进入本关时的生命、累计分数和升级，地图重新生成 |
| 选择关卡 | 可选第 1～35 关，确认后以 3 条命、0 分和初始火力开始新战役 |
| 返回游戏主菜单 | 暂存当前战场，仍可选择继续当前战役 |
| 操作说明 | 查看规则，返回后仍停留在暂停菜单 |
| 退出游戏／退出并返回大厅 | 确认后结束游戏进程；从 TUI Arcade 启动时由平台恢复大厅 |

每关消灭全部 20 辆敌军后进入结算菜单，可继续下一关、重试、选关、返回主菜单或退出。第 35 关胜利显示通关菜单。基地失守或生命耗尽进入失败菜单，默认选项是重试。

逐关继续保留生命、累计分数与升级。重试恢复关前快照，不叠加重复刷关分数。菜单、说明和选关均冻结战场；窗口缩小时自动暂停，恢复窗口后需主动继续。

## 经典关卡与规则

35 份原始地图和敌军配置位于 `tank_battle/stages/stage-1.json`～`stage-35.json`。地图按 13 × 13 大块解析为 52 × 52 子格，保留短／长十六进制砖墙、半块钢墙和基地缺口；坦克占 4 × 4 子格。渲染把纵向 4 个子格压入终端一行，80 × 24 窗口即可容纳完整地图。

- 每关 20 辆敌军，同时在场最多 4 辆；增援间隔按经典关卡编号逐渐缩短。
- 普通、快速、火力和装甲坦克依次值 100、200、300、400 分；快速坦克移动更快，火力坦克炮弹更快，装甲坦克需命中 4 次。
- 初始 3 条命；出生与复活后有 3 秒护盾，死亡清除火力升级。累计每 10000 分奖励 1 条命。
- 砖墙可击碎；钢墙阻挡普通炮弹，三级火力可破坏；水域挡车不挡炮；森林遮蔽敌军；冰面会滑行。
- 双方炮弹相遇或交叉可抵消；玩家误射基地也会导致失败。
- 消灭全部敌军才算胜利，没有等待 3 分钟自动获胜的规则。

第 4、11、18 辆敌军携带道具，首次被击中时随机掉落一个道具，15 秒后消失。拾取奖励 500 分：

| 道具 | ASCII 标记 | 效果 |
| --- | --- | --- |
| 星星 | `[*]` | 升一级火力：快炮弹、双炮弹、破钢墙，最高三级 |
| 坦克 | `[+]` | 增加 1 条命 |
| 头盔 | `[H]` | 10 秒护盾 |
| 时钟 | `[T]` | 敌军坦克冻结 10 秒，已发射的炮弹继续飞行 |
| 手雷 | `[G]` | 清除当前敌军 |
| 铁锹 | `[S]` | 基地外围钢墙保护 10 秒，结束后恢复原地形 |

这是终端操作的单人复刻：保留地图和出场队列，移动按 8 px 对齐；为使坦克能穿过被打通的砖墙，一炮打开坦克宽度的缺口。AI、射击节奏、冰面滑行与道具计时采用本项目的离散规则，不宣称与 FC 原版逐帧一致。当前没有双人、联机、地图编辑器或音效。

## 按键

| 按键 | 功能 |
| --- | --- |
| WASD / 方向键 | 战斗中移动转向，菜单中上下选择 |
| 空格 / J | 战斗中射击，菜单中确认 |
| Enter | 菜单确认、结算后默认继续／重试 |
| F | 自动连射 |
| P / Esc | 暂停／继续；在其它菜单中返回 |
| ? / H | 操作说明 |
| L | 选关 |
| PgUp / PgDn、Home / End | 选关翻页、首关／末关 |
| R | 结算后重试 |
| Q | 战斗／菜单中确认退出；说明／选关中返回 |
| Y / N | 确认／取消重新开始或退出 |

## 记录与来源

只保存最高分（`save_mode: records`），文件为游戏数据目录下的 `scores.json`。平台通过 `TUI_ARCADE_DATA_DIR` 分配目录；独立运行使用相同位置。最高分按累计战役分数记录，在关卡结算时保存。退出未结算关卡不保存当前增量分数。

首次运行会迁移旧记录；损坏记录保存到 `scores.json.corrupt*`，结算时提示备份名，写入失败不妨碍继续游戏。

经典关卡数据来自 MIT 开源项目 [feichao93/battle-city](https://github.com/feichao93/battle-city/tree/86c41c8c3c49cd27255bcf63167091d1061801fa)。详细范围见 [CREDITS.md](CREDITS.md)，上游许可证保留在 [LICENSE.battle-city](LICENSE.battle-city)。

## 开发与验证

- `levels.py`：原始数据加载、校验与子格展开。
- `rules.py`：不依赖终端的战斗、地形、敌军与道具规则。
- `app.py`：独立菜单、战役快照与终端界面。
- `glyphs.py`：彩色／ASCII 图案与地形压缩。
- `storage.py`：最高分读写与迁移。

在仓库根目录运行：

```sh
python3 -m unittest discover -s tests -p 'test_tank*.py'
python3 -m unittest discover -s tests -p 'test_storage.py'
```

覆盖关卡源数据校验、35 关连续通关、规则、菜单和真实伪终端操作。这些测试无需构建 Go 平台。打包时应随游戏包含 `stages/`、两份 LICENSE 和仓库 `kit/arcade_kit`。
